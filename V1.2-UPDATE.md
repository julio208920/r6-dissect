# R6 Match Stats v1.2 update (released as v1.2.1)

## Team Hub

Load a replay in Match Report, open Team Hub, enter a season and team name,
select players (or enter exact Siege usernames), and save the roster. Save
the current match to record tracked players. Season performance brings their
stats together and provides CSV and JSON exports. Match history shows the
saved matches. Repeated imports do not count a player-round twice.

The Windows app saves the database under `%LOCALAPPDATA%\R6MatchStats`;
updating the app does not overwrite it. Demo records and public-browser
sessions use separate temporary databases. Public browser data lasts only
for the session: export it before leaving. This release does not implement
shared online accounts or cloud synchronization.

Trade kills and multikill rounds are now included in persisted totals. Older
databases are upgraded without deleting records. Historical multikills are
recovered from saved round records; trade kills absent from old records
cannot be reconstructed without the original replay data. The CLI's old
`data/season_stats.db` can be used by passing its path to StatsManager.

## Match checking

Refresh replays retries failed parses and rescans nested files. Watch replay
folder checks every 15 seconds while Match Report is open and reloads changed
rounds. Saving season results remains an explicit action. Parsing warnings
remain visible and partial imports require acknowledgment before saving.
Mixed match IDs, duplicate round numbers, invalid team indices and malformed
CLI output produce actionable errors instead of misleading merged results.

EPS remains this app's relative match score, not Ubisoft's proprietary rating.
Replay statistics depend on the game's available replay events and parser
support; unsupported or missing events cannot be guaranteed accurate.

## Release checks

The Windows workflow runs Python and Go tests, builds the app, updates Defender
signatures, scans the installer, portable archive and unpacked app, and runs
the installation/window/uninstallation smoke test. Failed or unavailable
scans prevent uploading new release assets. If VT_API_KEY is configured,
VirusTotal must finish with usable results and no malicious/suspicious flags.
No key means Defender only, explicitly recorded in VirusScan.txt.

SHA256SUMS.txt contains artifact hashes. Compare against the trusted GitHub
release, for example:

```powershell
./desktop/verify-download.ps1 -File ./R6MatchStats-Setup.exe -ExpectedSHA256 <published-hash>
```

Hashes detect changed downloads; they do not replace code signing or provide
runtime anti-cheat or tamper prevention. The app does not scan game memory or
change Siege, BattlEye or Windows security settings.

The installed app also checks its scripts and replay parser against a SHA-256
manifest written at build time, and refuses to start if they have changed.

To rebuild an existing release, dispatch Windows app from main with
release_tag set to its tag (for example release_tag=v1.2.1). VirusScan.txt
records the exact source commit for that build. Existing assets are replaced
only after checks pass; the tag is not moved.
